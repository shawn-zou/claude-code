# 提示词工程基础

> **重要提示**：提示词工程是与 AI 有效沟通的核心技能。在 Claude Code 项目中，无论是编写 Agent 的 System Prompt，还是创建 Skill 的触发描述，都需要掌握提示词工程的基本原则。

---

## 一、什么是提示词工程？

### 1.1 定义

**提示词工程（Prompt Engineering）** 是设计和优化输入给 AI 模型的文本提示，以获得期望输出的技术和方法。

```
简单理解：
提示词 = 你给 AI 的指令
提示词工程 = 如何写好这个指令
```

### 1.2 为什么重要？

在 Claude Code 项目中，提示词工程无处不在：

| 场景 | 提示词的作用 |
|------|-------------|
| **Agent System Prompt** | 定义 Agent 的行为、职责、工作流程 |
| **Skill Description** | 决定 Skill 何时被触发 |
| **Hook Prompt** | 指导 AI 如何判断和处理 |
| **Command Description** | 说明命令的用途和用法 |

**一个例子：**

```markdown
❌ 糟糕的提示词：
"帮我检查代码"

✅ 好的提示词：
"你是代码审查专家。请审查 src/auth/ 目录下的代码，重点关注：
1. 安全漏洞（SQL 注入、XSS）
2. 错误处理是否完善
3. 是否遵循项目规范（CLAUDE.md）
输出格式：按严重程度分类，包含文件路径和行号。"
```

## 二、提示词设计核心原则

### 2.1 原则一：明确具体（Be Specific）

**核心思想：** AI 无法猜测你的意图，必须明确告诉它要做什么。

```markdown
❌ 模糊的提示词：
"分析一下这个代码"

✅ 明确的提示词：
"分析 src/auth/login.ts 文件中的 authenticate 函数：
1. 追踪函数调用链
2. 识别所有依赖项
3. 检查错误处理逻辑
4. 输出调用流程图"
```

**对比分析：**

| 维度 | 模糊提示词 | 明确提示词 |
|------|-----------|-----------|
| **目标** | 不清楚要分析什么 | 明确分析 authenticate 函数 |
| **范围** | 没有限定 | 指定文件和函数 |
| **方法** | 没有说明 | 列出具体步骤 |
| **输出** | 没有要求 | 要求输出流程图 |

### 2.2 原则二：提供上下文（Provide Context）

**核心思想：** AI 需要足够的背景信息才能做出正确的判断。

```markdown
❌ 缺少上下文：
"这个函数写得怎么样？"

✅ 提供完整上下文：
"这是一个用户认证函数，用于 Express.js 后端项目。
项目规范（CLAUDE.md）要求：
- 所有异步操作必须有 try-catch
- 错误必须使用 logger.error() 记录
- 返回值必须包含 success 和 message 字段

请根据这些规范评估这个函数。"
```

**上下文要素清单：**

```
✅ 项目背景 - 这是什么项目？
✅ 技术栈 - 使用什么框架/库？
✅ 规范约束 - 有什么编码规范？
✅ 目标用户 - 代码给谁用？
✅ 使用场景 - 在什么情况下使用？
```

### 2.3 原则三：结构化输出（Structure Output）

**核心思想：** 要求 AI 按特定格式输出，便于后续处理。

```markdown
❌ 没有输出格式要求：
"找出代码中的问题"

✅ 明确输出格式：
"找出代码中的问题，按以下格式输出：

## 严重问题
- [文件:行号] 问题描述 - 修复建议

## 警告
- [文件:行号] 问题描述 - 改进建议

## 建议
- 改进建议列表"
```

**常用输出格式：**

| 格式类型 | 适用场景 | 示例 |
|---------|---------|------|
| **Markdown 表格** | 对比分析 | 功能对比、参数说明 |
| **列表** | 问题清单 | Bug 列表、待办事项 |
| **代码块** | 代码示例 | 修复代码、实现方案 |
| **JSON** | 结构化数据 | 配置文件、API 响应 |
| **Mermaid 图** | 流程可视化 | 流程图、时序图 |

### 2.4 原则四：分步指导（Step-by-Step）

**核心思想：** 复杂任务拆分成步骤，让 AI 按步骤执行。

```markdown
❌ 一步到位：
"重构这个模块"

✅ 分步指导：
"重构这个模块，按以下步骤进行：

**Step 1: 分析现有结构**
- 列出所有文件和它们的职责
- 识别重复代码
- 标记耦合度高的部分

**Step 2: 设计新结构**
- 定义模块边界
- 设计接口
- 规划文件组织

**Step 3: 制定重构计划**
- 列出要修改的文件
- 确定修改顺序
- 评估风险点

**Step 4: 执行重构**
- 逐个文件修改
- 运行测试验证
- 更新文档"
```

### 2.5 原则五：提供示例（Give Examples）

**核心思想：** 示例比描述更有效，让 AI 理解期望的输出。

```markdown
❌ 只有描述：
"输出代码审查报告"

✅ 描述 + 示例：
"输出代码审查报告，格式如下：

## 代码审查报告

### 审查对象
- 文件：src/auth/login.ts
- 函数：authenticate()

### 问题列表

#### Critical（严重）
1. 🐛 SQL 注入风险
   - 位置：login.ts:45
   - 问题：使用字符串拼接 SQL
   - 修复：使用参数化查询

#### Warning（警告）
1. ⚠️ 缺少错误处理
   - 位置：login.ts:67
   - 问题：Promise 未捕获异常
   - 建议：添加 try-catch

### 总结
代码整体结构良好，但存在 1 个严重安全问题和 1 个警告需要修复。"
```

## 三、Claude Code 中的提示词应用

### 3.1 Agent System Prompt 设计

Agent 的 System Prompt 是提示词工程的典型应用。

**基本结构：**

```markdown
---
name: code-reviewer
description: Use this agent when...
model: inherit
color: red
---

You are [角色定义].

**Your Core Responsibilities:**
1. [职责 1]
2. [职责 2]

**Analysis Process:**
1. [步骤 1]
2. [步骤 2]

**Quality Standards:**
- [标准 1]
- [标准 2]

**Output Format:**
[输出格式说明]
```

**设计要点：**

| 要点 | 说明 | 示例 |
|------|------|------|
| **角色定义** | 明确 Agent 扮演什么专家 | "You are an expert code reviewer" |
| **职责清单** | 列出核心职责 | 1. 审查代码 2. 检查规范 |
| **工作流程** | 分步骤指导 | Step 1 → Step 2 → Step 3 |
| **质量标准** | 定义什么是好的输出 | "所有问题必须包含文件路径和行号" |
| **输出格式** | 明确输出结构 | Markdown 表格、列表、代码块 |

### 3.2 Skill Description 设计

Skill 的 Description 决定了何时触发 Skill。

**基本格式：**

```markdown
---
name: skill-name
description: This skill should be used when the user asks to "trigger phrase 1", "trigger phrase 2", "trigger phrase 3". [Additional context about when to use].
---
```

**设计要点：**

```markdown
✅ 好的 Description：
description: This skill should be used when the user asks to "create a hook", "add a PreToolUse hook", "validate tool use", "implement prompt-based hooks", or mentions hook events (PreToolUse, PostToolUse, Stop).

❌ 糟糕的 Description：
description: Use this skill for hooks.
```

**关键要素：**

1. **使用第三人称**："This skill should be used when..."
2. **包含触发短语**：用户可能说的具体话语
3. **覆盖多种表达**：同一意图的不同说法
4. **明确边界**：什么时候应该触发，什么时候不应该

### 3.3 Hook Prompt 设计

Hook 的 Prompt 用于指导 AI 进行判断。

**基本格式：**

```json
{
  "hooks": [
    {
      "event": "PreToolUse",
      "matcher": "Write",
      "type": "prompt",
      "prompt": "Before writing to [pattern], check:\n1. Is the file path correct?\n2. Are there any security concerns?\n3. Does this follow project conventions?\n\nIf any check fails, explain why and suggest alternatives."
    }
  ]
}
```

**设计要点：**

```markdown
✅ 好的 Hook Prompt：
"Before writing to .env files, verify:
1. No production secrets are being written
2. File permissions are appropriate
3. The .env file is in .gitignore

If any check fails, stop and explain the security risk."

❌ 糟糕的 Hook Prompt：
"Check if this is safe."
```

## 四、提示词优化技巧

### 4.1 迭代优化

提示词很少一次就完美，需要不断迭代。

**优化流程：**

```
1. 编写初始提示词
    ↓
2. 测试并观察输出
    ↓
3. 识别问题
    ↓
4. 修改提示词
    ↓
5. 再次测试
    ↓
重复直到满意
```

**示例：**

```markdown
第 1 版：
"审查这段代码"

问题：输出太笼统，没有具体问题

第 2 版：
"审查这段代码，找出 Bug 和安全问题"

问题：输出没有分类，难以阅读

第 3 版：
"审查这段代码，按以下分类输出：
- Critical：安全漏洞、严重 Bug
- Warning：潜在问题、代码异味
- Suggestion：改进建议

每个问题包含：文件路径、行号、描述、修复建议"

结果：输出清晰、可操作 ✅
```

### 4.2 使用分隔符

分隔符帮助 AI 区分不同部分的内容。

**常用分隔符：**

```markdown
# 标题分隔
## 二级标题
### 三级标题

--- 水平线分隔 ---

```代码块分隔```

**粗体分隔**

> 引用分隔

1. 列表分隔
```

**示例：**

```markdown
请分析以下代码：

---
```javascript
function authenticate(user, password) {
  // 代码内容
}
```
---

分析要求：
1. 安全性
2. 性能
3. 可读性
```

### 4.3 避免歧义

歧义会导致不可预测的输出。

```markdown
❌ 有歧义：
"检查这个文件"

✅ 清晰明确：
"检查 src/auth/login.ts 文件中的 authenticate 函数是否存在 SQL 注入风险"
```

**常见歧义来源：**

| 歧义类型 | 示例 | 改进 |
|---------|------|------|
| **代词指代不明** | "检查它" | "检查 authenticate 函数" |
| **范围不清** | "这个模块" | "src/auth/ 目录下的所有文件" |
| **标准模糊** | "好的代码" | "符合 CLAUDE.md 规范的代码" |
| **动词不明确** | "处理一下" | "重构并添加单元测试" |

### 4.4 利用 Few-Shot Learning

提供多个示例，让 AI 学习模式。

```markdown
请按以下格式输出代码审查结果：

示例 1：
---
文件：src/user.ts
问题：未处理的 Promise rejection
位置：第 45 行
严重程度：Warning
修复：添加 .catch() 处理
---

示例 2：
---
文件：src/auth.ts
问题：SQL 注入风险
位置：第 67 行
严重程度：Critical
修复：使用参数化查询
---

现在请审查以下代码：
[你的代码]
```

## 五、常见错误与避坑指南

### 5.1 错误一：提示词太长

**问题：** 提示词过长会导致 AI 忽略部分内容。

```markdown
❌ 过长的提示词（5000+ 字）：
[大量背景介绍]
[详细的历史说明]
[冗长的规范列表]
[重复的要求]
...

✅ 精简的提示词（500-1000 字）：
**背景**：Express.js 后端项目
**任务**：审查代码安全性
**重点**：SQL 注入、XSS、认证问题
**输出**：按严重程度分类的问题列表
```

**最佳实践：**
- Agent System Prompt：500-3000 字
- Skill Description：200-1000 字
- Hook Prompt：100-500 字

### 5.2 错误二：指令冲突

**问题：** 多个指令相互矛盾，AI 不知道该听谁的。

```markdown
❌ 指令冲突：
"快速完成代码审查，但要非常详细地分析每一行代码"

✅ 明确优先级：
"进行代码审查，优先关注安全问题。如果时间允许，再检查代码风格。"
```

### 5.3 错误三：假设 AI 有记忆

**问题：** AI 不会记住之前的对话（除非在同一会话中）。

```markdown
❌ 假设有记忆：
"继续刚才的分析"

✅ 提供上下文：
"继续分析 src/auth/ 目录的代码安全性。之前我们已经发现了 SQL 注入问题，现在请检查其他安全问题。"
```

### 5.4 错误四：忽略边界情况

**问题：** 只考虑正常情况，没有处理边界情况。

```markdown
❌ 没有边界处理：
"分析这个函数"

✅ 包含边界处理：
"分析这个函数，考虑以下情况：
1. 正常输入
2. 空输入
3. 非法输入
4. 极端情况（如超大输入）"
```

## 六、实战练习

### 练习 1：优化 Agent System Prompt

**原始版本：**

```markdown
You are a code reviewer. Review code and find problems.
```

**优化后的版本：**

```markdown
You are an expert code reviewer specializing in modern software development.

**Your Core Responsibilities:**
1. Review code for bugs and security vulnerabilities
2. Check adherence to project guidelines (CLAUDE.md)
3. Identify code quality issues

**Review Process:**
1. Read the code files using Read tool
2. Scan for common issues:
   - Security: SQL injection, XSS, authentication flaws
   - Bugs: Null handling, race conditions, logic errors
   - Quality: Code duplication, missing error handling
3. Rate each issue with confidence score (0-100)
4. Only report issues with confidence ≥ 80

**Output Format:**
## Code Review Report

### Critical Issues
- [file:line] Issue - Fix

### Warnings
- [file:line] Issue - Recommendation

### Summary
[Overall assessment]
```

### 练习 2：设计 Skill Description

**场景：** 创建一个帮助用户编写单元测试的 Skill

**答案：**

```markdown
---
name: unit-test-generator
description: This skill should be used when the user asks to "write unit tests", "generate tests", "add test coverage", "create test cases", or mentions testing frameworks (Jest, Mocha, Vitest). Provides guidance on test structure, assertions, mocking, and coverage best practices.
---
```

### 练习 3：设计 Hook Prompt

**场景：** 创建一个防止删除重要文件的 PreToolUse Hook

**答案：**

```json
{
  "event": "PreToolUse",
  "matcher": "Bash",
  "type": "prompt",
  "prompt": "Before executing Bash commands that delete files (rm, rmdir, del), verify:\n\n1. Is the target path correct?\n2. Are there any important files that should not be deleted?\n3. Is the user aware this is a destructive operation?\n\nIf deleting files in critical directories (src/, lib/, config/), warn the user and ask for confirmation.\n\nCritical directories: src/, lib/, config/, .claude/, plugins/"
}
```

## 七、总结

### ✅ 核心要点

1. **明确具体** - 不要让 AI 猜测你的意图
2. **提供上下文** - 给 AI 足够的背景信息
3. **结构化输出** - 要求特定格式便于处理
4. **分步指导** - 复杂任务拆分步骤
5. **提供示例** - 示例比描述更有效
