# 04-插件配置管理

## 🎯 本章导读

插件配置管理让插件从"硬编码"走向"可定制化"。通过 `.local.md` 文件，用户可以灵活调整插件行为而无需修改代码。

**你将学到**：
- ✅ .local.md 配置文件的两种用途
- ✅ YAML frontmatter 解析技术
- ✅ 从 Hook/Command/Agent 中读取配置
- ✅ 配置的优先级规则
- ✅ 实战：创建可配置的插件

**前置知识**：
- 了解插件基本结构（参考 01-插件系统详解.md）
- 基本的 Bash 命令知识

**预计耗时**：1-1.5 小时

## 一、配置文件模式详解

### 1.1 两种配置文件对比

在插件系统中，有两种主要的配置方式：

#### 方式 1：Hookify 规则配置（已学习）

```
.claude/hookify.rule-name.local.md
   │
   └── 用于定义 Hook 规则（02 章详解）
```

**特点**：
- ✅ 声明式规则定义
- ✅ 基于 pattern/conditions 匹配
- ✅ 立即生效

---

#### 方式 2：插件状态配置（本章重点）

```
.claude/plugin-name.local.md
   │
   └── 用于存储插件配置和状态
```

**特点**：
- ✅ 存储用户自定义设置
- ✅ 管理插件运行状态
- ✅ 支持复杂数据结构

**对比**：

| 特性 | Hookify 规则 | 插件状态配置 |
|------|------------|-------------|
| **用途** | 定义 Hook 规则 | 存储配置/状态 |
| **命名** | `hookify.*.local.md` | `plugin-name.local.md` |
| **读取方** | Hookify 引擎 | Hooks/Commands/Agents |
| **示例** | `hookify.dangerous-rm.local.md` | `multi-agent-swarm.local.md` |

---

### 1.2 文件位置与命名

**标准位置**：
```
你的项目目录/
└── .claude/
    ├── hookify.dangerous-rm.local.md    # Hookify 规则
    ├── multi-agent-swarm.local.md       # 多 Agent 协作配置
    ├── ralph-loop.local.md              # Ralph 迭代循环配置
    └── my-plugin.local.md               # 你的插件配置
```

**命名规则**：
```
.claude/<plugin-name>.local.md
         │            │
         │            └── 固定后缀
         └── 插件名称（与 plugin.json 中的 name 一致）
```

**实际案例**：
```bash
# security-guidance 插件
.claude/security-guidance.local.md

# feature-dev 插件
.claude/feature-dev.local.md

# 你的插件
.claude/my-awesome-plugin.local.md
```

**重要提醒**：
- ⚠️ 必须在 `.claude/` 目录下
- ⚠️ 必须使用 `.local.md` 后缀
- ⚠️ 文件名要与插件名一致
- ⚠️ 应该添加到 `.gitignore`

## 二、YAML Frontmatter 详解

### 2.1 基本结构

**.local.md 文件 = YAML frontmatter + Markdown body**

```markdown
---
enabled: true              # 布尔值
strict_mode: false         # 布尔值
max_retries: 3             # 数值
notification_level: info   # 字符串
allowed_extensions:        # 数组
  - ".js"
  - ".ts"
coordinator_session: team-leader  # 字符串
---

# Additional Context

这里是 markdown 正文，可以包含：
- 任务描述
- 额外指令
- 反馈给 Claude 的提示
- 文档或笔记
```

---

### 2.2 字段类型示例

#### 布尔字段

```yaml
---
enabled: true
strict_mode: false
auto_deploy: true
---
```

**在脚本中读取**：
```bash
ENABLED=$(echo "$FRONTMATTER" | grep '^enabled:' | sed 's/enabled: *//')

if [[ "$ENABLED" == "true" ]]; then
  echo "插件已启用"
else
  exit 0  # 禁用时快速退出
fi
```

---

#### 数值字段

```yaml
---
max_retries: 3
max_iterations: 10
timeout_seconds: 300
---
```

**在脚本中读取**：
```bash
MAX_RETRIES=$(echo "$FRONTMATTER" | grep '^max_retries:' | sed 's/max_retries: *//')

# 验证数值范围
if ! [[ "$MAX_RETRIES" =~ ^[0-9]+$ ]] || [[ $MAX_RETRIES -lt 1 ]] || [[ $MAX_RETRIES -gt 100 ]]; then
  echo "⚠️  Invalid max_retries in settings (must be 1-100)" >&2
  MAX_RETRIES=3  # 使用默认值
fi
```

---

#### 字符串字段

```yaml
---
notification_level: info
validation_mode: strict
coordinator_session: team-leader
---
```

**在脚本中读取**：
```bash
LEVEL=$(echo "$FRONTMATTER" | grep '^notification_level:' | sed 's/notification_level: *//')

case "$LEVEL" in
  info)
    echo "信息级别：info"
    ;;
  warning)
    echo "信息级别：warning"
    ;;
  error)
    echo "信息级别：error"
    ;;
esac
```

---

#### 数组字段

```yaml
---
allowed_extensions: [".js", ".ts", ".tsx"]
dependencies:
  - "Task 3.4"
  - "Task 3.5"
blocked_commands:
  - "rm -rf"
  - "mkfs"
---
```

**在脚本中读取**：
```bash
# 简单数组（单行）
EXTENSIONS=$(echo "$FRONTMATTER" | grep '^allowed_extensions:' | sed 's/allowed_extensions: *//')

# 复杂数组（多行）- 需要更复杂的解析
# 建议使用 Python 或专门的 YAML 工具
```

## 三、配置读取技术

### 3.1 从 Hooks 中读取（Bash 脚本）

#### 完整示例：安全检查 Hook

```bash
#!/bin/bash
set -euo pipefail

# 定义配置文件路径
STATE_FILE=".claude/security-scan.local.md"

# 快速退出：文件不存在
if [[ ! -f "$STATE_FILE" ]]; then
  exit 0  # 插件未配置，跳过
fi

# 提取 YAML frontmatter（--- 之间的内容）
FRONTMATTER=$(sed -n '/^---$/,/^---$/{ /^---$/d; p; }' "$STATE_FILE")

# 读取 enabled 字段
ENABLED=$(echo "$FRONTMATTER" | grep '^enabled:' | sed 's/enabled: *//')

# 检查是否启用
if [[ "$ENABLED" != "true" ]]; then
  exit 0  # 插件已禁用
fi

# 读取其他配置
STRICT_MODE=$(echo "$FRONTMATTER" | grep '^strict_mode:' | sed 's/strict_mode: *//')
MAX_FILE_SIZE=$(echo "$FRONTMATTER" | grep '^max_file_size:' | sed 's/max_file_size: *//')

# 根据配置调整行为
if [[ "$STRICT_MODE" == "true" ]]; then
  echo "🔒 严格模式：执行全面检查" >&2
  # 执行严格的安全检查
  # ...
else
  echo "⚠️  标准模式：执行基础检查" >&2
  # 执行标准安全检查
  # ...
fi

# 使用数值配置
if [[ -n "$MAX_FILE_SIZE" ]] && [[ $MAX_FILE_SIZE -gt 0 ]]; then
  echo "📊 最大文件大小：$MAX_FILE_SIZE bytes" >&2
fi
```

---

#### 解析技术详解

**技术 1：提取 Frontmatter**

```bash
# 方法：提取 --- 之间的所有内容
FRONTMATTER=$(sed -n '/^---$/,/^---$/{ /^---$/d; p; }' "$FILE")

# 解释：
# /^---$/    - 匹配以 --- 开头的行
# /^---$/    - 匹配结束的 ---
# { /^---$/d; p; } - 删除 --- 行，打印其他行
```

**技术 2：读取单个字段**

```bash
# 字符串字段
VALUE=$(echo "$FRONTMATTER" | grep '^field_name:' | sed 's/field_name: *//' | sed 's/^"\(.*\)"$/\1/')

# 布尔字段
ENABLED=$(echo "$FRONTMATTER" | grep '^enabled:' | sed 's/enabled: *//')
# 比较：if [[ "$ENABLED" == "true" ]]; then

# 数值字段
MAX=$(echo "$FRONTMATTER" | grep '^max_value:' | sed 's/max_value: *//')
# 使用：if [[ $MAX -gt 100 ]]; then
```

**技术 3：提取 Markdown Body**

```bash
# 提取第二个 --- 之后的所有内容
BODY=$(awk '/^---$/{i++; next} i>=2' "$FILE")

# 解释：
# /^---$/  - 匹配 --- 行
# {i++; next} - 计数器加 1，跳过该行
# i>=2     - 当遇到第二个 --- 后，打印后续所有行
```

## 四、配置优先级规则

### 4.1 优先级的三个层次

```
优先级从高到低：

1️⃣ 用户明确指定（最高）
   └── 命令行参数、环境变量
   
2️⃣ .local.md 配置文件
   └── 项目特定配置
   
3️⃣ 插件默认值（最低）
   └── 硬编码的默认行为
```

---

### 4.2 实际应用示例

**场景：验证插件的严格程度**

```bash
#!/bin/bash

# 层次 3：默认值（最低优先级）
DEFAULT_MODE="standard"
DEFAULT_MAX_RETRIES=3

# 从环境变量读取（高层次优先级）
MODE_FROM_ENV="${VALIDATION_MODE:-}"

# 从配置文件读取（中间优先级）
STATE_FILE=".claude/validation-plugin.local.md"
if [[ -f "$STATE_FILE" ]]; then
  FRONTMATTER=$(sed -n '/^---$/,/^---$/{ /^---$/d; p; }' "$STATE_FILE")
  CONFIG_MODE=$(echo "$FRONTMATTER" | grep '^mode:' | sed 's/mode: *//')
  CONFIG_MAX_RETRIES=$(echo "$FRONTMATTER" | grep '^max_retries:' | sed 's/max_retries: *//')
else
  CONFIG_MODE=""
  CONFIG_MAX_RETRIES=""
fi

# 应用优先级（高优先级覆盖低优先级）
FINAL_MODE="${MODE_FROM_ENV:-${CONFIG_MODE:-$DEFAULT_MODE}}"
FINAL_MAX_RETRIES="${CONFIG_MAX_RETRIES:-$DEFAULT_MAX_RETRIES}"

echo "最终模式：$FINAL_MODE"
echo "最大重试：$FINAL_MAX_RETRIES"
```

**优先级逻辑**：
```bash
# 如果 VALIDATION_MODE 环境变量存在 → 使用环境变量
# 否则如果 .local.md 存在且有 mode → 使用配置文件
# 否则 → 使用默认值
```

### 4.3 配置文件之间的优先级

**问题**：如果有多个配置文件，谁优先级更高？

**答案**：** specificity（特异性）原则**

```
项目根目录/.claude/plugin.local.md  ← 全局配置（低优先级）
    vs
src/.claude/plugin.local.md         ← 目录特定配置（高优先级）
```

**实际案例**：

```bash
# 全局配置（项目根目录）
/project/.claude/linter.local.md
---
mode: standard
max_file_size: 100000

# 目录特定配置（src 目录）
/project/src/.claude/linter.local.md
---
mode: strict
max_file_size: 50000  # 更严格的要求
```

**读取逻辑**：
```bash
# 优先读取当前目录的配置文件
if [[ -f ".claude/linter.local.md" ]]; then
  # 使用当前目录的配置
  CONFIG_FILE=".claude/linter.local.md"
else
  # 回退到项目根目录
  CONFIG_FILE="../.claude/linter.local.md"
fi
```

## 五、实战：创建可配置的插件

### 实战目标

创建一个可配置的代码质量检查插件，支持：
- ✅ 启用/禁用开关
- ✅ 严格模式切换
- ✅ 自定义检查项
- ✅ 灵活的阈值配置

---

### 步骤 1：设计配置结构

```markdown
<!-- .claude/code-quality.local.md -->
---
enabled: true
strict_mode: false
max_function_length: 50
max_file_size: 10000
check_console_log: true
check_todo_count: 3
allowed_file_types:
  - ".ts"
  - ".tsx"
  - ".js"
---

# Code Quality Plugin Configuration

This plugin checks code quality during development.

**Current Settings:**
- Standard mode (not strict)
- Max function length: 50 lines
- Max TODO count: 3 per file
```

---

### 步骤 2：创建 Hook 脚本

```bash
#!/bin/bash
set -euo pipefail

# plugins/code-quality/hooks/scripts/check-quality.sh

# 配置文件路径
CONFIG_FILE=".claude/code-quality.local.md"

# 快速退出：未配置
if [[ ! -f "$CONFIG_FILE" ]]; then
  exit 0
fi

# 读取配置
FRONTMATTER=$(sed -n '/^---$/,/^---$/{ /^---$/d; p; }' "$CONFIG_FILE")
ENABLED=$(echo "$FRONTMATTER" | grep '^enabled:' | sed 's/enabled: *//')

# 检查是否启用
if [[ "$ENABLED" != "true" ]]; then
  exit 0
fi

# 读取其他配置
STRICT_MODE=$(echo "$FRONTMATTER" | grep '^strict_mode:' | sed 's/strict_mode: *//')
MAX_FUNCTION_LENGTH=$(echo "$FRONTMATTER" | grep '^max_function_length:' | sed 's/max_function_length: *//')
CHECK_CONSOLE_LOG=$(echo "$FRONTMATTER" | grep '^check_console_log:' | sed 's/check_console_log: *//')

# 从输入中获取文件内容
INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // ""')
CONTENT=$(echo "$INPUT" | jq -r '.tool_input.content // ""')

# 只检查配置的文件类型
if ! echo "$FILE_PATH" | grep -qE '\.(ts|tsx|js)$'; then
  exit 0
fi

# 检查 1：函数长度
FUNCTION_COUNT=$(echo "$CONTENT" | grep -cE '^function\s+\w+\s*(' || true)
if [[ $FUNCTION_COUNT -gt 0 ]]; then
  # 简化示例：实际应该统计每个函数的行数
  echo "⚠️  检测到 $FUNCTION_COUNT 个函数，请确保每个函数不超过 $MAX_FUNCTION_LENGTH 行" >&2
fi

# 检查 2：console.log（如果启用）
if [[ "$CHECK_CONSOLE_LOG" == "true" ]]; then
  CONSOLE_COUNT=$(echo "$CONTENT" | grep -c 'console\.log' || true)
  if [[ $CONSOLE_COUNT -gt 0 ]]; then
    echo "⚠️  发现 $CONSOLE_COUNT 个 console.log，生产环境应该移除" >&2
  fi
fi

# 检查 3：TODO 注释
TODO_COUNT=$(echo "$CONTENT" | grep -ci '// TODO' || true)
if [[ $TODO_COUNT -gt 3 ]]; then
  echo "⚠️  发现 $TODO_COUNT 个 TODO 注释，建议及时清理" >&2
fi

# 严格模式额外检查
if [[ "$STRICT_MODE" == "true" ]]; then
  echo "🔒 严格模式：执行额外检查" >&2
  # 添加更多严格检查...
fi

exit 0
```

# Code Quality Plugin

claude plugins install /path/to/code-quality-plugin

## 配置

在项目根目录创建 `.claude/code-quality.local.md`：

```markdown

## 配置说明

### enabled (布尔值)
是否启用插件。默认：`true`

### strict_mode (布尔值)
严格模式。默认：`false`

**严格模式额外检查：**
- 要求所有公共函数有 JSDoc
- 禁止使用 `any` 类型
- 要求完整的错误处理

### max_function_length (数值)
函数最大行数。默认：`50`

### check_console_log (布尔值)
是否检查 console.log。默认：`true`

### check_todo_count (数值)
允许的 TODO 注释最大数量。默认：`3`

## 使用

配置完成后，每次编辑文件时自动检查。

**无需重启**，保存配置文件后下次编辑立即生效。

## 示例配置

---
```

## 六、最佳实践

### 6.1 文件命名

✅ **推荐做法：**

### 6.3 提供默认值

**良好实践：代码中提供合理的默认值**

```bash
#!/bin/bash

# 默认值
DEFAULT_MAX_RETRIES=3
DEFAULT_MODE="standard"

# 尝试从配置读取
if [[ -f "$CONFIG_FILE" ]]; then
  # 读取配置
  MAX_RETRIES=$(...)
  MODE=$(...)
else
  # 使用默认值
  MAX_RETRIES=$DEFAULT_MAX_RETRIES
  MODE=$DEFAULT_MODE
fi

# 始终有可用的值
echo "使用配置：max_retries=$MAX_RETRIES, mode=$MODE"
```

**好处**：
- ✅ 插件开箱即用
- ✅ 用户可以选择性配置
- ✅ 避免配置缺失导致的错误

### 6.4 验证配置

**始终验证用户输入的配置：**

```bash
# 验证数值范围
MAX=$(echo "$FRONTMATTER" | grep '^max_value:' | sed 's/max_value: *//')

if ! [[ "$MAX" =~ ^[0-9]+$ ]] || [[ $MAX -lt 1 ]] || [[ $MAX -gt 100 ]]; then
  echo "⚠️  Invalid max_value in settings (must be 1-100)" >&2
  MAX=10  # 使用合理的默认值
fi

# 验证枚举值
MODE=$(echo "$FRONTMATTER" | grep '^mode:' | sed 's/mode: *//')

case "$MODE" in
  strict|standard|lenient)
    # 有效值
    ;;
  *)
    echo "⚠️  Invalid mode '$MODE', using 'standard'" >&2
    MODE="standard"
    ;;
esac
```

## 七、真实案例解析

### 案例 1：multi-agent-swarm 插件

**配置文件**：

```markdown
<!-- .claude/multi-agent-swarm.local.md -->
---
agent_name: auth-implementation
task_number: 3.5
pr_number: 1234
coordinator_session: team-leader
enabled: true
dependencies: ["Task 3.4"]
additional_instructions: Use JWT tokens, not sessions
---

# Task: Implement Authentication

Build JWT-based authentication for the REST API.

Coordinate with auth-agent on shared types.
```

**Hook 如何使用**：

```bash
# agent-stop-notification.sh

STATE_FILE=".claude/multi-agent-swarm.local.md"

# 快速退出
if [[ ! -f "$STATE_FILE" ]]; then
  exit 0
fi

# 解析配置
FRONTMATTER=$(sed -n '/^---$/,/^---$/{ /^---$/d; p; }' "$STATE_FILE")
COORDINATOR=$(echo "$FRONTMATTER" | grep '^coordinator_session:' | sed 's/coordinator_session: *//')
AGENT_NAME=$(echo "$FRONTMATTER" | grep '^agent_name:' | sed 's/agent_name: *//')
ENABLED=$(echo "$FRONTMATTER" | grep '^enabled:' | sed 's/enabled: *//')

# 如果启用，通知协调者
if [[ "$ENABLED" == "true" ]]; then
  # 发送 tmux 通知
  tmux send-keys -t "$COORDINATOR" "Agent $AGENT_NAME completed task" Enter
fi
```

**核心价值**：
- ✅ 动态配置 Agent 任务
- ✅ 无需修改代码即可调整行为
- ✅ 支持团队协作（通知协调者）

### 案例 2：ralph-wiggum 插件

**配置文件**：

```markdown
<!-- .claude/ralph-loop.local.md -->
---
iteration: 1
max_iterations: 10
completion_promise: "All tests passing and build successful"
---

Fix all the linting errors in the project.
Make sure tests pass after each fix.
```

**Hook 如何使用**：

```bash
# stop-hook.sh

STATE_FILE=".claude/ralph-loop.local.md"

if [[ ! -f "$STATE_FILE" ]]; then
  exit 0  # 未激活循环
fi

# 解析配置
FRONTMATTER=$(sed -n '/^---$/,/^---$/{ /^---$/d; p; }' "$STATE_FILE")
ITERATION=$(echo "$FRONTMATTER" | grep '^iteration:' | sed 's/iteration: *//')
MAX_ITERATIONS=$(echo "$FRONTMATTER" | grep '^max_iterations:' | sed 's/max_iterations: *//')
COMPLETION=$(echo "$FRONTMATTER" | grep '^completion_promise:' | sed 's/completion_promise: *//')

# 提取正文（要执行的提示）
PROMPT=$(awk '/^---$/{i++; next} i>=2' "$STATE_FILE")

# 检查是否达到最大迭代
if [[ $ITERATION -ge $MAX_ITERATIONS ]]; then
  echo "已达到最大迭代次数 $MAX_ITERATIONS"
  exit 0
fi

# 检查完成条件
if echo "$TRANSCRIPT" | grep -q "$COMPLETION"; then
  echo "✅ 完成条件满足：$COMPLETION"
  exit 0
fi

# 更新迭代次数
NEW_ITERATION=$((ITERATION + 1))
sed -i "s/^iteration: .*/iteration: $NEW_ITERATION/" "$STATE_FILE"

# 继续循环
echo "继续迭代 $NEW_ITERATION/$MAX_ITERATIONS"
```

**核心价值**：
- ✅ 控制迭代循环次数
- ✅ 动态更新状态
- ✅ 灵活的完成条件

## 八、常见问题 FAQ

### Q1: 配置文件修改后多久生效？

**A**: ⚠️ **需要重启 Claude Code！**

这与 Hookify 规则不同：

| 配置类型 | 生效时间 |
|---------|---------|
| Hookify 规则 | 立即生效 |
| 插件状态配置 | 需要重启 |

**原因**：
- Hookify 规则由 Hook 引擎动态读取
- 插件状态配置在启动时加载到内存

**正确流程**：
```bash
1. 编辑 .claude/my-plugin.local.md
2. 保存文件
3. 退出 Claude Code: exit
4. 重新启动：claude
5. 新配置生效
```

---

### Q2: 如何临时禁用插件？

**A**: 三种方法

**方法 1：设置 enabled: false**

```markdown
---
enabled: false  # 临时禁用
mode: standard
---
```

**方法 2：重命名文件**

```bash
mv .claude/my-plugin.local.md .claude/my-plugin.local.md.bak
```

**方法 3：删除文件**（不推荐）

```bash
rm .claude/my-plugin.local.md
# 需要时再创建
```

**推荐**：使用方法 1，方便恢复

---

### Q3: 多个配置文件会冲突吗？

**A**: 不会，遵循特异性原则

```bash
# 场景 1：不同插件的配置文件
.claude/security-guidance.local.md    ← 安全插件
.claude/feature-dev.local.md          ← 功能开发插件
# 互不干扰

# 场景 2：同一项目的不同配置
.claude/plugin.local.md               ← 全局配置
src/.claude/plugin.local.md           ← src 目录特定配置
# 在 src 目录下，特异性配置优先级更高
```

---

### Q4: 配置文件会影响性能吗？

**A**: 几乎无影响

**实测数据**：
- 读取配置文件：< 1ms
- 解析 frontmatter: < 5ms
- 总体开销：可忽略不计

**优化建议**：
- ✅ 使用快速退出模式（文件不存在立即返回）
- ✅ 只在必要时读取配置
- ✅ 缓存解析结果（如果需要多次读取）
