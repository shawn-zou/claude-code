# 阶段转换与进度追踪

七阶段流程的核心原则之一是**按顺序执行，不要跳过任何阶段**。本章将详细讲解如何判断每个阶段的完成情况、如何进行阶段转换、以及如何使用 TodoWrite 机制追踪进度。

---

## 📋 一、为什么需要阶段转换控制？

### 1.1 常见问题

**❌ 错误做法示例：**

```
用户：帮我做个登录功能

Claude: 好的，让我开始写代码...
        → 直接跳到 Phase 5（实现）
        
问题爆发：
❌ 需求理解不准确
❌ 架构设计缺失
❌ 返工成本极高
```

**✅ 正确做法：**

```
用户：帮我做个登录功能

Claude: 好的，让我们按照标准流程来：
        Phase 1: Discovery → Phase 2: Exploration → 
        Phase 3: Clarification → Phase 4: Architecture → 
        Phase 5: Implementation → Phase 6: Review → 
        Phase 7: Summary
        
结果：高质量、少返工、易维护
```

---

### 1.2 阶段转换的三个关键问题

在每个阶段结束时，都需要问自己：

1. **这个阶段的产出物完整吗？**
   - 是否完成了所有必要的活动？
   - 是否生成了所有必要的文档？

2. **这个阶段的质量达标吗？**
   - 产出物是否符合质量标准？
   - 是否有明显的遗漏或错误？

3. **可以进入下一个阶段了吗？**
   - 前置条件是否满足？
   - 用户是否确认？

## 🎯 二、TodoWrite 进度追踪机制

### 2.1 什么是 TodoWrite？

**TodoWrite** 是 feature-dev 插件中使用的进度追踪工具，用于：
- 跟踪七阶段流程的执行进度
- 确保不跳过任何阶段
- 提供可视化的进度展示
- 帮助管理复杂的开发任务

**在 feature-dev.md 中的明确规定：**
```markdown
## Core Principles

- **Use TodoWrite**: Track all progress throughout
```

---

### 2.2 TodoWrite 的基本用法

**语法格式：**

```markdown
/todo [任务描述]
```

**常用操作：**

| 操作 | 语法 | 示例 |
|------|------|------|
| 创建任务 | `/todo 任务描述` | `/todo Phase 1: Discovery` |
| 标记完成 | `/done 任务描述` | `/done Phase 1: Discovery` |
| 查看列表 | `/todos` | 显示所有待办事项 |

### 2.5 TodoWrite 的最佳实践

#### ✅ 正确做法

**1. 尽早创建 Todo 列表**
```markdown
// 在 Phase 1 开始时就创建完整列表
/todo 功能开发：XXX
  /todo Phase 1: Discovery
  /todo Phase 2: Exploration
  ...
```

**2. 及时更新状态**
```markdown
// 完成一个子任务就立即标记
/done Phase 1: 理解业务目标
/done Phase 1: 识别目标用户
```

**3. 细化任务粒度**
```markdown
// ❌ 太粗糙
- [ ] Phase 5: Implementation

// ✅ 合适粒度
- [ ] 读取相关文件
- [ ] 编写核心代码
- [ ] 编写单元测试
- [ ] 代码自测
```

**4. 保持可见性**
```markdown
// 定期查看进度
/todos

// 输出当前进度
已完成：Phase 1-4 (60%)
进行中：Phase 5: Implementation
待开始：Phase 6-7
```

---

#### ❌ 避免的错误

**错误 1：事后补 Todo**
```
❌ 先做完所有事情，再回头补 Todo 列表
✅ 边做边更新，保持同步
```

**错误 2：粒度过粗**
```
❌ - [ ] Phase 5: Implementation
✅ - [ ] 编写核心代码
   - [ ] 编写单元测试
   - [ ] 代码自测
```

**错误 3：忘记更新**
```
❌ 做完了不标记完成
✅ 完成后立即标记 ✓
```

### 4.2 自动化检查脚本

**检查脚本示例：**

```javascript
// check-phases.js
const phases = [
  'Phase 1: 需求发现报告',
  'Phase 2: 代码库探索',
  'Phase 3: 需求规格说明',
  'Phase 4: 架构设计文档',
  'Phase 5: 代码 + 测试',
  'Phase 6: 质量审查报告',
  'Phase 7: 项目总结'
];

function checkPhaseCompletion() {
  let completedPhases = 0;
  
  phases.forEach(phase => {
    if (phaseExists(phase)) {
      console.log(`✓ ${phase} 已完成`);
      completedPhases++;
    } else {
      console.log(`✗ ${phase} 未完成`);
    }
  });
  
  const completionRate = (completedPhases / phases.length) * 100;
  console.log(`\n完成率：${completionRate.toFixed(0)}%`);
  
  if (completionRate < 100) {
    console.log('\n⚠️  警告：有阶段未完成，不能停止！');
    return false;
  }
  
  console.log('\n✅ 所有阶段完成，可以停止！');
  return true;
}
```

### 6.3 常见陷阱与避免

#### 陷阱 1：跳跃阶段

**❌ 错误做法：**
```
Phase 1 → Phase 5（直接开始编码）
```

**✅ 正确做法：**
```
Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5
```

**避免方法：**
- 使用 TodoWrite 强制追踪
- Stop Hook 自动验证
- 定期检查阶段完整性

---

#### 陷阱 2：阶段混淆

**❌ 错误做法：**
```
在 Phase 2 做 Phase 4 的事（边探索边设计）
```

**✅ 正确做法：**
```
Phase 2: 只探索，不设计
Phase 4: 专注设计
```

**避免方法：**
- 明确每个阶段的目标
- 阶段开始时重申任务
- 发现偏离时及时纠正

---

#### 陷阱 3：过度拖延

**❌ 错误做法：**
```
Phase 1 花了 3 天（应该 1 天）
Phase 2 花了 1 周（应该 2 天）
```

**✅ 正确做法：**
```
遵循建议的时间分配
前期（1-4）：45-65%
后期（5-7）：35-55%
```

**避免方法：**
- 设定时间盒（Time Box）
- 使用番茄工作法
- 定期回顾时间使用
